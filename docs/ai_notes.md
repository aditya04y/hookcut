# AI notes

Running log of places where AI tools got something wrong (the solution doc must name one).

## Lead notes
- 2026-11-19 Prior research script (an earlier audit of the pack) parsed labels case-sensitively and silently dropped Episode 6 (uppercase SCENE labels: 2 scenes, 97 blocks). HookCut parses labels case-insensitively.
- 2026-11-19 First parser version read "MATRIARCH (O.S.) (Firm)" as delivery "O.S.) (Firm" (one greedy regex for nested parentheticals). Caught by printing voice-over samples; fixed to collect each (...) group.
- 2026-11-19 Quick model probe on Ep 1: Groq qwen3.8-27b and gpt-oss-120b both chose a whispered "[the groom's name]?" as the strongest hook; Gemini 4 Hydrogen chose "[the rival sister's reveal]." Small models over-weight the first emotional line, not the most scroll-stopping one.

## Worker notes
- 2026-11-19 editor (Claude): first draft of export.still_frame() carried a dead line, `next(... and False)`, that always evaluated to None. It changed no output, so every test passed; caught only by re-reading the module before the smoke run. Passing tests do not show that every line does something.
- 2026-11-19 evaluator (Claude): first independence check took the run judge's family from the config spec and each verdict's `model`, but with fallbacks both hold the whole chain ("qwen -> gpt-oss-120b -> gpt-oss-20b"; judge.py stores `client.spec`), so it flagged gpt-oss as "used by the run" even when only Qwen answered (and would have missed it had Qwen failed over). Caught by a dry run against a chain spec; fixed by reading the models that actually answered from the run log.
- 2026-11-19 analyst (Claude): across 5 prompt iterations on Ep 1, Groq gpt-oss-120b left "[the rival sister's reveal]." (E01.B027) out of its notable beats in 4 of 5 runs (once at medium effort) and rated "[a change-of-heart line]." H5 instead. It missed the father's silent refusal every time and 3 times put the ending cliffhanger on the SFX string swell or the cut to black, even after the prompt said "a music swell is not a cliff". Gemini 3.8 Flash on the same prompt got B027 H5, "[the bride's plea to her father]." C4 (resolved_by the father's silence) and the story-beat ending. Caught by fixed sanity targets in the dev loop. Lesson: the fallback is a real quality drop, so the run log must name the model that scored each episode.
- 2026-11-19 analyst (Claude): Groq returned HTTP 413 "Request too large ... TPM Limit 8000, Requested 8469" for a ~5.5K-token analyze call made within a minute of another; the same request passed 65 s later. The OpenAI SDK retries 429 but not 413, so on the free tier a parallel analyze run would silently fall through to placeholders. Caught when a dev call came back as "analysis failed".
- 2026-11-19 analyst (Claude): the cold-viewer judge reads names and relationships that a viewer would not get from the video: speaker labels ("LADY [HEROINE]") and camera directions ("her elderly father", "the groom and her sister"). Its standalone scores are probably optimistic. Seen in the judge's own premises on hand-made clips.
- 2026-11-19 lead: first full run at analysis concurrency 6 lost ~1 in 8 episodes (E04, E16, E21…) to Gemini free-tier 429s; each failed only after the whole fallback chain (3.8 Flash → 4 Hydrogen → 3.5 Flash-Lite) gave up. Diagnosed by replaying E04 alone (429 within 2 s). Fix: rerun with concurrency 2 — cached episodes cost nothing, failed ones retry. Production would use the paid tier or batch API.
- 2026-11-19 lead: on the 11 episodes scored by both, Gemini 3.5 Flash-Lite agreed with the stronger Gemini models (3.8 Flash / 4 Hydrogen) on the strongest hook in 6/11 episodes but on the strongest cut point in only 1/11 — Flash-Lite parks its top cliffhanger on the episode's last beat, the stronger models find mid-episode cut points (e.g. E01 "[the bride's plea to her father]."). - 2026-11-19 evaluator (Claude): both cold-viewer judges ignore the prompt rule "you only know someone's name if a line says it out loud": the premise/conflict names a character never named aloud in 44/64 Qwen verdicts and 15/20 gpt-oss-120b verdicts (role titles excluded), reading names from speaker tags, which flatters `standalone`. Caught by counting names in verdicts against the clip's spoken lines; fix by anonymising unspoken speaker tags in judge.clip_text.
- 2026-11-19 evaluator (Claude): the eval judge gpt-oss-120b gave standalone 3-4 and keep_watching 2-4 on all 60 eval clips (never a 5 or 1), so its "pass" is close to a hook_lands test; vs the run's Qwen judge on the top-20: 45% verdict agreement, kappa -0.00, every disagreement pass vs borderline. A judge's pass rate means little without its score spread and a second judge.
- 2026-11-19 engagement (Claude): my first engagement model added every numeric feature from `story_graph.episode_features` to the regression. When the genome worker's version landed with ~50 numbers per episode, the 30-episode test season over-fitted: the held-out episode Brier was worse than the base rate (0.083 vs 0.077), and planted-sign recovery fell to 0.61 for continuation. The planted-recovery and holdout tests caught it; neither the unit tests nor the CLI run flagged anything. Fix: a fixed core model, with each extra feature screened one at a time on top of it. Lesson: on a 50-episode show, more story features means less signal unless they are tested one at a time.
- 2026-11-19 genome (Claude): two alias errors, one from each side. Gemini 3.5 Flash-Lite filled the show-level `same_as` field (meant for character ids) with 20 alias strings ("Lady [Heroine]", "THE [DESCRIPTOR]", "girl"), so it made only 3 real merges; it also tagged an off-list emotion ("pain") 3 times and gave a reveal a beat id from the wrong episode (E06.B037 for E26). Code accepts ids only, counts the strings in one warning and drops the bad beat. Upstream, the E03 analysis listed another character's descriptor ("LADY IN [COLOUR] GOWN") as the groom's alias; a title-gender guard drops that claim. My own first mention index took "given names" from descriptor aliases ("in" from LADY IN GREEN, "her" from "Her Grace") and put the rival sister in all 50 episodes. Caught by checking each character's episode span against the analyses' cast lists.
- 2026-11-20 graph→rank worker (Claude): the story graph resolved titles and role words as identity aliases: the scheming rival carried "Duchess", "Duchess of [Family Name]" and "disgraced bride", the heroine "wife", "maid", "sister", the hero "veteran", "husband". In this show the heroine becomes the Duchess, so a title claimed for one person in E41 could resolve another person's lines later (the bidder resolver's reused-company-name error). Caught by reading run_full/story_graph.json. Fix (code only, same cached show-level reply): an analysis alias that is a bare role word, contains a title, or is a description nobody is labelled by becomes a time-scoped role (CharacterNode.roles, kept only with an evidence beat: 38 claims → 29 roles, 4 without evidence left out). It still resolves that episode's speaker labels but never votes across episodes, never merges characters and is no longer in the alias table; script labels such as THE HOODED STRANGER, LADY IN GREEN and CART DRIVER stay identities.
